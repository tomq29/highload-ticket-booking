# Highload Ticket Booking System 🎫

Этот проект — твой тренажер для прокачки навыков Highload, PostgreSQL, Kafka и Observability.
Мы будем строить систему бронирования билетов, которая должна выдерживать конкурентную нагрузку (когда 1000 человек хотят купить 1 билет).

## Уровень 1: Транзакции и Конкурентность (PostgreSQL)

**Цель:** Реализовать API для бронирования билета, которое гарантирует, что одно место не будет продано дважды.

### 📝 Задание

1.  **Спроектировать схему БД:**
    - Таблица `events` (концерты).
    - Таблица `seats` (места). У места должен быть статус (`available`, `booked`, `sold`) и `version` (для оптимистичных блокировок, если выберешь их).
    - Таблица `tickets` (выданные билеты).
2.  **Реализовать HTTP хендлер `POST /book`:**
    - Принимает: `event_id`, `seat_id`, `user_id`.
    - Логика: Проверяет, свободно ли место. Если да — бронирует (меняет статус) и создает запись в `tickets`.
    - **Важно:** Все должно работать в транзакции.
3.  **Обеспечить Data Consistency:**
    - Если два запроса прилетают одновременно на одно место, только один должен победить. Второй должен получить ошибку (409 Conflict).

### 🛠 Технические требования

- Язык: **Go**
- БД: **PostgreSQL** (драйвер `pgx`)
- Миграции: SQL-файлы или `golang-migrate` (на твой выбор).
- Архитектура: Clean Architecture (Handler -> Service -> Repository).

### ✅ Критерии приемки (Definition of Done)

1.  Проект запускается через `docker-compose up`.
2.  Есть миграция, создающая таблицы.
3.  Есть `seed` данных (скрипт или эндпоинт), который создает 1 ивент и 100 мест.
4.  **Главный тест:** Ты запускаешь скрипт (я дам пример на k6 или просто bash-скрипт), который делает 50 одновременных запросов на бронирование **одного и того же места**.
    - **Ожидание:** Ровно 1 запрос вернет 200 OK. Остальные 49 вернут ошибку. В базе место забронировано 1 раз.
